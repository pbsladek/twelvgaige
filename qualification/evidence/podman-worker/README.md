# Podman worker qualification — 2026-08-02

This directory records qualification of the Linux/ARM64 Codex worker on the dedicated `twelvgaige` Podman machine. The qualified image is:

```text
localhost/twelvgaige/worker:codex-0.146.0@sha256:60a67653db8b2f6561b221837ea9069a7c65355be957fc89b2ce9fc9665401c5
```

The image uses Alpine 3.23.5 and contains the checksum-pinned Codex CLI 0.146.0 native ARM64 bundle, Git, and CA certificates. It runs as UID/GID 65532 and contains no credentials.

## Recorded evidence

- `image-record.json` is the canonical provenance and supply-chain result.
- `image-record.sig` is its detached Ed25519 signature. The matching public key is checked in; the private qualification key remains under Twelvgaige's application-data root.
- `sbom.spdx.json` is the full SPDX SBOM generated by Syft 1.44.0.
- `vulnerabilities.json` is the full Grype 0.112.0 result.
- `security-review.json` records the vulnerability policy and applicability decisions.
- `image-inspect.json` is Podman's image inspection output.
- `catalog.json` is the admission record consumed by the live qualification scripts.
- `live-qualification.json` records machine, launch, mount, network, limit, recovery, cancellation, credential-revocation, and performance results.
- `codex-provider-qualification.json` records the provider-authenticated coding fixture without recording credential values.

The scan found zero critical and zero unreviewed high findings. Grype reported one high-severity Git finding, CVE-2026-32631. The advisory concerns Git for Windows and NTLM authentication; the worker contains Linux/ARM64 Git and has no Windows or NTLM authentication path, so the review marks it not applicable.

The detached signature proves that the local qualification key signed this exact record. It is not an OCI registry signature or a transparency-log entry. A release pipeline should replace or supplement it with the chosen registry signing and verification system before publishing the image.

## Live boundary result

The live suite passed with a non-root user, read-only root filesystem, all capabilities dropped, `no-new-privileges`, an exact writable workspace mount, no network, inspected CPU/memory/PID limits, crash resume, drift quarantine, descendant cancellation, credential revocation, and two concurrent sessions.

The authenticated Codex fixture uses an explicit outer-authoritative profile. Podman supplies the attested sandbox, while Codex runs in its documented externally sandboxed automation mode; this is selected by policy and is never an automatic fallback. Earlier failed iterations exposed a worker-image defect rather than a need for more container capabilities: the worker account pointed at a bundled glibc-linked `zsh` that could not run on Alpine. The qualified image uses `/bin/sh`. The worker remained non-root, read-only, capability-free, resource-limited, and writable only at its isolated workspace. Local Codex auth existed only in container tmpfs, exact long credential values were checked against the workspace and captured outputs, and the container was destroyed after the run.

## Reproduce

```sh
make podman-machine-health
make podman-worker-qualify-image
make podman-live-qualify
make podman-codex-provider-qualify
```

The provider command requires an existing supported local Codex login. It sends the small fixture to the provider. The other commands do not use provider credentials.

Verify the current detached signature with:

```sh
openssl pkeyutl -verify \
  -pubin \
  -inkey qualification/evidence/podman-worker/qualification-signing-public-key.pem \
  -rawin \
  -in qualification/evidence/podman-worker/image-record.json \
  -sigfile qualification/evidence/podman-worker/image-record.sig
```
